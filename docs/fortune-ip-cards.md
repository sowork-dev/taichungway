# 在地物件卡（IP 閃卡）設計 v1

取代 `fortune-spec.md` 中「34 張政策卡」的卡片內容部分；流程（轉 → 開 → 分享、每頁一個主要按鈕）、福氣冊、分享與交換的規則仍沿用該規格。
設計稿：`docs/design/fortune-ip-cards.html`（需用 http 開啟，同資料夾的 `fortune-ip-cards.json` 為資料）。

## 1. 核心想法

**政策文件裡提到的建設、物件、節慶，各自成為一張有插圖的卡**，而不是把政策標題做成卡。每張卡是一個在地的東西，大家可以討論「這個我認得」「這個比較強」。

## 2. 參考：寶可夢卡牌（只借版面與規則概念，不使用任何美術、名稱或程式）

> 資料來源是 [Card Codex 的卡面符號說明](https://cardcodex.com/blog/what-do-the-symbols-on-pokemon-cards-mean/)、[Event Horizon Hobbies 的入門文章](https://www.eventhorizonhobbies.com/blogs/blog/learn-to-play-the-pokemon-trading-card-game)等零售與愛好者網站，不是官方規則書；若要完整照搬規則，需再對照官方資料。

| 寶可夢卡牌 | 本專案的對應 |
|---|---|
| 名稱、屬性圖示、HP（左上到右上） | 卡名、屬性圓圈、**戰鬥力 CP**（右上） |
| 插圖框 | 物件插圖框（原創；正式版由設計師繪製） |
| 招式：能量費用、傷害 | 招式名稱、費用圓點、傷害（＝人氣） |
| 弱點 ×2、抗性 −30、撤退費用 | 弱點 ×2、抗性 −30、換場成本 |
| 稀有度符號（● ◆ ★）、編號、系列符號 | ● ◆ ★ ✦、`008/015`、「文化旗艦」 |
| 屬性相剋 | 4 屬性環狀相剋（老城›聲音›場館›山城›老城） |

## 3. 卡片版面（卡面 5:7，設計稿 300×440）

1. 名稱＋屬性圓圈＋CP
2. 插圖框（左下小標：屬性・所屬政策）
3. 狀態列：**照文件寫**，如「文件稱：2030 年完工」「文件提出：升級」，不寫成已完成
4. 招式：費用、名稱、傷害
5. 人氣／底蘊／規模（0–99）
6. 弱點／抗性／換場
7. 稀有度符號、編號、系列名、插畫標示

卡背（點卡翻面）：福氣幣、文件怎麼寫、對應政策、來源文件、數值依據（設定值或公開數字換算）、聲明（遊戲數值不是政策評價；提案不等於已實施；非官方互動、未取得競選團隊授權或背書）。

## 4. 數值規則（公開、可驗算）

- **CP＝人氣＋底蘊＋規模**。
- 招式傷害＝人氣取到 10；招式費用與換場成本＝規模每 30 點 1 顆（最少 1）。
- **規模**：文件有公開席位數時，1 點＝500 席（巨蛋 15,000→30、超巨蛋 45,000→90、副場館 5,000→10）；否則為設計設定值。
- **人氣、底蘊**：全部是設計設定值，卡背標示「設定值」，不代表事實。
- 屬性相剋：弱點受到 ×2、抗性受到 −30；環狀相剋，沒有最強屬性，不代表任何地區或政策優劣。
- 稀有度（● 60%、◆ 28%、★ 10%、✦ 2%）只代表**抽到的機會**，與強弱、政策重要性無關；機率公開。

## 5. 第一彈「文化旗艦」原型：5 個政策、15 張

| 政策（來源：提供的文件） | 物件卡 |
|---|---|
| 臺中車站出發，啟動「臺中文化門戶計畫」 | 臺中驛、第二市場、宮原眼科 |
| 推動星光計畫，點亮活化舊城區 | 新民街倉庫群、流行影音中心、鐵支路開唱 |
| 打造臺中成為流行音樂與表演藝術之都 | 臺中巨蛋、臺中超巨蛋、巨蛋副場館 |
| 文化產業國際化，打造臺中文化品牌 | 后里薩克斯風、潭子爵士鼓、霧峰音樂鈴 |
| 升級「東勢客家文化園區」 | 東勢客家園區、新丁粄、巧聖仙師祭 |

分佈：普通 7、稀有 4、超稀有 3、傳說 1；屬性：老城 3、場館 5、聲音 4、山城 3。

**內容守則**
1. 物件名稱與數字只取自提供的政策文件；不補預算、期程、成效。
2. 不畫、不使用任何人物肖像；巧聖仙師只畫匠人工具，不畫神像。
3. 文件內部備註（如「可以不用在記者會講」）與對外比較數據不進卡片。
4. 狀態列照文件措辭；預計完工年份一律寫「文件稱」。
5. 全部卡片須人工核對與簽核後才可上線；插畫目前為原創草稿，正式版需設計師重畫，並確認建築、地標的圖像使用方式。

## 6. 卡牌說明頁

設計稿 ① 為「怎麼看一張卡」：一張實卡加 9 個編號標註與說明。上線時放在福氣冊右上「說明」小標籤，頁面只有一個主要按鈕（「回到福氣冊」）。內容：卡面各部分、數值規則、屬性相剋表、稀有度與機率。

## 7. 網路上討論：稀有度與戰鬥力

不需要伺服器就能做的：
- 卡牌詳情頁的「分享」：1080×1350 圖片，含卡面與 CP、稀有度、編號。
- **並排比較頁**（設計稿 ⑥）：兩張卡、CP、屬性相剋與傷害試算，一鍵分享比較圖，貼到社群討論。

需要伺服器、**本階段不做**的：全站排行榜、卡片真偽驗證、即時對戰。若之後要做卡牌對戰，可沿用現有泡泡 PK 的即時後端架構，另寫規格。

## 8. 待決定

1. **內容核對**：誰負責核對 15 張（及後續各彈）的名稱、狀態列與數字？
2. **插畫**：是否由設計師正式繪製？地標（如臺中驛、綠美圖）使用圖像的授權與風格要求？
3. **數值**：人氣、底蘊是否由你們設定？（我只能給設計草稿，不代表事實。）
4. **戰鬥力**：目前只做比較與試算，是否需要之後做真正的卡牌對戰？
5. **下一彈**：還想把哪些政策與物件做成卡？（例如綠美圖、歌劇院、行動長照車、公車與轉運站、東勢的大茅埔龍神山水祭。）
6. **稀有度機率**：60／28／10／2 是否保留？

## 9. 實作狀態

`/fortune/` 已完成（舊的長按版在 `/fortune/classic/`）：
- 轉（繞把手一圈，或按「轉」）→ 開 → 揭曉；點卡翻面看來源；每個畫面只有一個主要按鈕。
- 15 張在地物件卡、4 種稀有度（公開機率 60／28／10／2）、10% 閃卡版本、CP 與屬性相剋。
- 福氣冊（n/15、重複張數、閃卡標記）、說明、清除進度；進度只存本機（`taichung-fortune-v2`，格式驗證失敗整份不採用）。
- **送朋友**：多出來的普通卡可用連結送出（`#gift=v1.<卡號>.<檢查碼>`，在網址 `#` 之後，不會送到伺服器）。連結只含卡號，無法變出更稀有的卡，閃卡不能送；沒有伺服器，所以同一連結可被多人各收一張（說明內已寫明）。送出時從福氣冊扣掉一張。
- **成就卡**：集滿 15 張後，福氣冊的主要按鈕變為「分享成就卡」（1080×1350，本機繪製）。
- **並排比較**：福氣冊內「比較」，選兩張自己有的卡，顯示 CP、雙向傷害試算，可分享比較圖。
- 分享圖皆在瀏覽器本機繪製，不含暱稱與位置。

尚未做 / 上線前需要：
- 內容核對簽核、設計師正式插畫、手機實機與真人計時。
- 更多「彈」（第二批政策與物件）。
- 全站排行榜、伺服器驗證的真正交換、卡牌對戰（需要後端，另寫規格）。
